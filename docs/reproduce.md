Every number in the report can be regenerated by running the testbenches below in order. Two routes are documented: **Linux (the canonical flow: Cadence Virtuoso + Spectre)** and **Windows (remote access, or an open-source substitute)**.

**Measurement conventions (all testbenches)**
- V_DD = 1.1 V, 25 °C (conditions fixed by the assignment)
- Propagation delay t_pd: the time between the input and output crossings of V_DD/2 = **550 mV**. Rising and falling transitions are each measured 5 times and averaged.
- Rise/fall time: **0.2 V_DD → 0.8 V_DD (220 mV → 880 mV)**
- Unit inverter: L = 45 nm, W_n = 1.1 μm, W_p = 2.2 μm

# 1. Linux — Cadence Virtuoso + Spectre (canonical flow)

This is exactly how the original project was run. Prerequisites: **a university/lab Linux server account, a Cadence license, and a 45 nm educational PDK**. All three have to come from the school; installing them on a personal machine violates the license. (Library and device names in the examples depend on the server environment — substitute the names used by your PDK.)

## 1.1 Connecting to the server

```bash
# Connect with X11 forwarding so the GUI renders on the local machine
ssh -X student_id@server.address
# e.g. ssh -X user@ymsicl-x4.yonsei.ac.kr   (per lab instructions)
```

If the remote GUI feels sluggish, request a VNC/X2Go/NoMachine session instead — much more comfortable (check with the TA).

## 1.2 Environment setup and launch

```bash
# Source the setup script distributed by the lab/course (sets PDK paths and the license server)
source /PDK_path/setup.csh        # or whatever command your .bashrc documents
cd ~/project && virtuoso &
```

The working directory must contain `cds.lib` (library registration) and `.cdsinit`. Example `cds.lib`:

```
INCLUDE /PDK_path/cds.lib       ; PDK libraries (tsmcN28, etc.)
DEFINE Tutoring ./Tutoring      ; my working library
```

## 1.3 Building the library and the schematics

1. **Library Manager** → File → New → Library → enter a name → "Attach to an existing technology library" → select the PDK tech lib (e.g. tsmcN28)
2. New → Cell View → `INV` (schematic)
3. **Schematic Editor shortcuts**: `i` add instance → pick a PDK device from the browser (e.g. `nch_ulvt_mac`, `pch_ulvt_mac` — LVT/HVT/ULVT are V_th flavors; a higher V_th is the better choice for low-power applications), `w` wire, `l` wire label (nets sharing a label are connected without drawing a wire), `q` edit properties (change W/L, e.g. W = 1.1u/2.2u), `c` copy, `m` move, `r` rotate, `u` undo, `f` fit to window, `x` check and save
4. A device Width can also be left as a **variable** (e.g. `C_gate`) so it can be swept
5. Testbench cell `tb_INV`: place `vdc` (1.1 V), `vpulse` (input clock), `cap` (load), and `gnd` from `analogLib`

## 1.4 Running ADE Explorer

1. From the schematic: Launch → **ADE Explorer** → simulator: **spectre**
2. Analyses → `tran`, Stop time = 10n (long enough to observe several toggles)
3. **Design Variables**: register e.g. `C_gate`, then give it `0.1f:0.1f:1f` or a value list for a parametric sweep
4. Outputs → check the nodes to observe (input and output) → **Netlist and Run** (green ▶)
5. In the waveform viewer (ViVA):
   - Drop two markers `a` and `b` — dx (time difference) and dy (voltage difference) are displayed automatically, which is enough to read rise time (220 → 880 mV) and t_pd (550 mV crossing)
   - Or automate it with the built-in functions under Tools → **Calculator**:
     - `delay(v("/IN") 0.55 1 "rising" v("/OUT") 0.55 1 "falling")` → t_pd
     - `riseTime(v("/OUT") 0.22 t 0.88 t nil "time")` → t_r
6. Parametric results overlay one waveform per sweep value, which is how the slope-matching point is identified (TB-0a)

## 1.5 Construction notes per testbench

- **TB-0a (gate cap)**: two copies of a 3-stage unit-inverter chain. Copy A drives the device under test through its **gate only** (NMOS: D/S/B → VSS; PMOS: D/S/B → VDD); copy B drives an `analogLib cap` (variable `C_gate`). Sweep C_gate from 0.1f to 1f — the value at which the two output waveforms have identical slopes is the gate cap.
- **TB-0b (drain cap)**: same structure, but the signal node is tied to the **drain instead of the gate** (NMOS: G/S/B → VSS, drain → node).
- **TB-0c (mobility)**: cap at the end of an inverter chain. Measure the rising delay (220 → 880 mV) and the falling delay 5 times each, then sweep the W_p:W_n ratio to find the ratio where t_r = t_f.
- **TB-0d (FO1/FO4)**: FO1 loads the DUT with one identical inverter, FO4 with a 4× load (or four inverters in parallel). Three input-shaping inverter stages ahead of the DUT are mandatory. τ = (t_FO4 − t_FO1)/3, p_inv = t_FO1/τ − 1.
- **TB-2 (R_eff)**: bias the device in the linear region and extract the I–V slope from a DC sweep; the reciprocal of the slope is R_eff.
- **TB-3/4 (wire)**: model one wire section as **three π segments** (~3% accuracy): series R = R_w·l/3 per segment, node capacitance C = C_w·l/6 … distributed π-style. The repeater is two inverter stages with the same drive strength as the driver (NOR2). Build N = 3/4/5 as separate schematics and compare.
- **TB-5 (crosstalk)**: two identical wire ladders, with C_adj = 0.3 fF/μm × (l / number of segments) tied between the two lines at every segment. Three simulations: Case 1 in-phase transition / Case 2 neighbor held quiet / Case 3 anti-phase transition.

## 2.2 Route B — local open-source reproduction on Windows (ngspice + PTM 45 nm)

Without any license, the **circuit topology, measurement methodology, and trends** reproduce completely. Note only that the process model is different, so absolute values will differ from the report (for comparison against the report, treat this as a "trend agreement" check).

### Installation

1. Download an ngspice Windows build from https://ngspice.sourceforge.io → extract `ngspice-xx_64.7z` (e.g. to `C:\ngspice`)
2. Download the PTM 45 nm models from https://ptm.asu.edu → "45nm_HP" (high performance) → save as `45nm_HP.pm`
   - The model card device names are `nmos`/`pmos`; it is a bulk CMOS process in the 1.0–1.1 V class
3. Put the netlists (.cir) and the model file in the same working folder, then:

```bash
C:\ngspice\bin\ngspice.exe tb0a_gatecap.cir
```

### TB-0a — Gate capacitance (slope matching)

```spice
* tb0a_gatecap.cir — gate cap extraction by slope matching
.include 45nm_HP.pm
.param VDD=1.1

.subckt inv in out vdd vss
MP out in vdd vdd pmos W=2.2u L=45n
MN out in vss vss nmos W=1.1u L=45n
.ends

VDD vdd 0 {VDD}
VIN in  0 PULSE(0 {VDD} 1n 20p 20p 2n 4n)

* chain A: 3-inv shaping + DUT nmos (gate load) — D/S/B tied to VSS
XA1 in  a1  vdd 0 inv
XA2 a1  a2  vdd 0 inv
XA3 a2  outA vdd 0 inv
MDUT 0 outA 0 0 nmos W=1.1u L=45n

* chain B: 3-inv shaping + ideal cap
XB1 in  b1  vdd 0 inv
XB2 b1  b2  vdd 0 inv
XB3 b2  outB vdd 0 inv
CL  outB 0 0.2f

.tran 1p 12n

.control
foreach cg 0.1f 0.2f 0.3f 0.4f 0.5f 0.6f 0.7f 0.8f 0.9f 1.0f
  alter CL $cg
  run
  meas tran trA TRIG v(outA) VAL=0.22 RISE=2 TARG v(outA) VAL=0.88 RISE=2
  meas tran trB TRIG v(outB) VAL=0.22 RISE=2 TARG v(outB) VAL=0.88 RISE=2
end
.endc
.end
```

→ The `cg` at which `trA ≈ trB` is the gate capacitance. (For the pMOS, change `MDUT` to `pmos W=2.2u` with D/S/B → vdd and repeat.)

### TB-0b — Drain capacitance

Only the DUT connection changes relative to TB-0a: write it as `MDUT outA 0 0 0 nmos W=1.1u L=45n`, i.e. **drain on outA** with gate/source/bulk tied to 0 (VSS). (For the pMOS, reference everything to vdd.)

### TB-0d — FO1 / FO4 delay

```spice
* tb0d_fo4.cir
.include 45nm_HP.pm
.param VDD=1.1
.subckt inv in out vdd vss m=1
MP out in vdd vdd pmos W={2.2u*m} L=45n
MN out in vss vss nmos W={1.1u*m} L=45n
.ends
VDD vdd 0 {VDD}
VIN in 0 PULSE(0 {VDD} 1n 20p 20p 2n 4n)
* 3 shaping stages -> DUT -> FO4 load (4x inverter) -> second load (keeps the observed node clean)
X1 in  n1 vdd 0 inv
X2 n1  n2 vdd 0 inv
X3 n2  n3 vdd 0 inv
XD n3  n4 vdd 0 inv          ; DUT
XL n4  n5 vdd 0 inv m=4      ; FO4 load
XL2 n5 n6 vdd 0 inv m=16
.tran 1p 12n
.meas tran tpdf TRIG v(n3) VAL=0.55 RISE=2 TARG v(n4) VAL=0.55 FALL=2
.meas tran tpdr TRIG v(n3) VAL=0.55 FALL=2 TARG v(n4) VAL=0.55 RISE=2
.end
```

For FO1, change `m=4` on `XL` to `m=1`. Then τ = (t_FO4 − t_FO1)/3 and p_inv = t_FO1/τ − 1.

### TB-3 — Non-repeated wire (π-model, 3 segments)

```spice
* tb3_wire_pi3.cir — l=200um, Rw=100ohm/um (20k total), Cw=0.2fF/um (40fF total)
.include 45nm_HP.pm
.param VDD=1.1
.subckt inv in out vdd vss m=1
MP out in vdd vdd pmos W={2.2u*m} L=45n
MN out in vss vss nmos W={1.1u*m} L=45n
.ends
VDD vdd 0 {VDD}
VIN in 0 PULSE(0 {VDD} 1n 20p 20p 4n 8n)
X1 in n1 vdd 0 inv
X2 n1 drv vdd 0 inv m=2          ; driver (NOR2 equivalent in the report)
* 3-segment pi ladder: R=6.667k per segment, node caps split 6.67f/13.3f/13.3f/6.67f
Rw1 drv  w1 6.667k
Rw2 w1   w2 6.667k
Rw3 w2   rcv 6.667k
Cp0 drv 0 6.667f
Cp1 w1  0 13.333f
Cp2 w2  0 13.333f
Cp3 rcv 0 6.667f
Crcv rcv 0 7.226f                 ; receiver input cap
.tran 1p 20n
.meas tran tpd TRIG v(n1) VAL=0.55 FALL=2 TARG v(rcv) VAL=0.55 RISE=2
.end
```

### TB-4 — Repeated wire (N = 4)

Four sections of l/4 = 50 μm. Scale the ladder above down to R = 5 k / C = 10 fF per section and insert a repeater (two inverter stages, same drive strength as the driver) between sections. Build the N = 3 and N = 5 versions as well and compare t_pd to find the minimum.

### TB-5 — Crosstalk

```spice
* two identical wire ladders lineA/lineB, coupling cap at every segment node
Cc1 a_w1 b_w1 20f      ; Cadj=0.3fF/um × 200um/3seg ≈ 20f per node
Cc2 a_w2 b_w2 20f
Cc3 a_rcv b_rcv 20f
* Case1: VB in phase with VA / Case2: VB = DC 0 / Case3: VB anti-phase pulse
.meas tran trA TRIG v(a_rcv) VAL=0.22 RISE=1 TARG v(a_rcv) VAL=0.88 RISE=1
```

Check that the trA ratio across the three cases roughly follows C_gnd : C_gnd+C_adj : C_gnd+2C_adj (report: 1 : 1.94 : 5.41).

### TB-1 / TB-6 — Source/destination logic

Define NAND2/NOR2/NAND4/NAND3 as subcircuits (using the W values from Tables 4.3 and 4.6 of the report), assemble the 8-stage path, then measure t_pd at the 550 mV crossing and verify the truth table by toggling (reproducing the a0/a1/s0b waveforms of Table 2.6).

# 4. Common Pitfalls

1. **The X11 GUI never appears** → on MobaXterm, verify X11-Forwarding in the session settings; if `echo $DISPLAY` is empty, reconnect. It can also be an `xauth` problem on the server side — ask the TA.
2. **`.step` errors in ngspice** → ngspice does not support `.step`. Use `foreach` + `alter` inside a `.control` block (as in the examples above).
3. **PTM model device name mismatch** → check the name in the model card's `.model NMOS nmos ...` line and make the M-device model name in the netlist match it.
4. **Measurement fails (meas failed)** → confirm that the RISE/FALL occurrence numbers in TRIG/TARG actually exist in the waveform, and that the transient window is long enough relative to the 1 ns pulse delay.
5. **Measuring before the waveform has settled** → the first cycle is affected by initial conditions, so measure on the second or later edge (`RISE=2`, etc.). The report likewise averages 5 measurements.
6. **Same label in Virtuoso but no connection** → the label has to sit exactly on the wire. Check for floating-net warnings in Check and Save (`x`).
